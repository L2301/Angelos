# Image generation and editing: clean-room alternatives

**Research date: 2026-10-06. Status: research only; not implemented, downloaded, trained, or benchmarked.**

Scope comes from supplied functional requirements. No private implementation/catalog is copied into Angelos; equivalence is functional, not an acceptance oracle. Evidence below comes from public first-party model cards, repositories, licenses, and framework documentation inspected on the research date.

## Recommendation and evidence boundary

Evaluate a **portfolio**, not a purported drop-in Rhizome replacement:

- **General generation/editing:** FLUX.2 Klein 4B; retain Qwen-Image-2512 for text-to-image and Qwen-Image-Edit-2511 for reference editing.
- **Specialists:** original Qwen-Image plus InstantX ControlNet for spatial controls; Qwen-Image-Layered for RGBA decomposition; BiRefNet/SAM 2.1 for extraction; RealESRNet/Real-ESRGAN for restoration; OmniSVG 1.1 8B and VTracer for vectors.
- **Compositions:** masked sampling plus pixel compositing, canvas extension, and tiled generation require explicit workflow contracts. They are not native capabilities of every generator.
- **Quarantine:** restrictive checkpoints and unresolved license chains belong in a separately approved research lane, not an “open-source” production default.

These are proposed evaluation priorities, not measured rankings. **Direct** means a released model or documented pipeline accepts the relevant inputs; it does not mean exact preservation, quality parity, or Angelos support. **Composed** means additional processing/models are required. **Partial** means some requested semantics remain unsupported or unverified. Gaps are bounded to the inspected releases, not claims that no solution exists anywhere.

They are **out of scope and not covered by image checkpoints**, requiring separate master-matrix rows and fail-loud dispatch. Repeating a still image is not interpolation or a validated seamless loop. This document does not claim those sibling capabilities are implemented.

## Proposed compositions and integration requirements

All items in this section are **design requirements**, not existing nodes or verified execution paths.

1. **Typed, backend-independent IR.** Version distinct operations for generation, reference edit, strength-based img2img, masked fill, control conditioning, decomposition, segmentation, restoration, creative upscale, vectorization, training and adapter attachment. Fail loudly on unsupported combinations; never ignore a mask/control image or silently switch checkpoints.
2. **Asset contracts.** Record dimensions, color space, transfer function, dtype/range and RGB/RGBA mode. Define edit mask `1 = regenerate`, preservation mask `0 = retain`, soft-feather behavior and resizing rules. For depth, declare relative/metric, near/far polarity and normalization. For layers, specify canvas, z-order, straight versus premultiplied alpha, blend mode and requested/returned layer count.
3. **Strict localized edits.** Proposed path: mask preparation (optionally SAM) → Qwen latent inpainting → RGB composite with the unchanged source outside the approved edit/feather region. Outpainting adds explicit padding and image-origin coordinates. Reference masks in IP-Adapter constrain attention; they are not inpainting masks or pixel-preservation guarantees.
4. **Reference binding.** Preserve ordered reference IDs and roles (`subject`, `style`, `layout`), crop transforms and strength semantics. Advertise independent reference strengths only for a tested backend. Do not conflate a contact sheet with native multi-reference conditioning.
5. **Separate fidelity modes.** Restoration defaults to conservative processing with an unchanged-source option; creative upscale explicitly permits synthesis. A proposed permissive creative route uses resampling, overlapping Qwen img2img tiles, shared context and seam blending. No evidence here proves it matches SUPIR or any proprietary creative upscaler.
6. **Vector safety.** Parse SVG as untrusted data. Reject scripts, event handlers, external URLs, entity expansion and unsafe `foreignObject`; enforce token/path/coordinate/resource budgets. Rasterize in a sandbox. A PNG embedded in SVG does not satisfy vector generation; preserve fonts or outline text under separately cleared font licenses.
7. **Artifact admission.** Before any later download, approve exact repository revision, filenames, hashes, model architecture, code commit, licenses/notices, dependencies and intended use. Separate `code_license`, `weights_license`, `data_license`, and `commercial_review_status`; deny unknown/conflicting chains. Quantization or an Apache adapter cannot remove base restrictions.
8. **Offline execution; explicit retrieval exception.** No graph-controlled shell, arbitrary Python, remote loading or `trust_remote_code` execution. Reviewed custom code must be pinned and packaged in advance. Missing weights must fail without network access. Disable hosted text encoders, Hub pushes and external experiment trackers; upstream examples are not safe defaults. Diffusers training examples include tracking/upload flags, and BFL loaders can auto-fetch missing artifacts. [Trainer defaults/examples](https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_flux2.md), [BFL loader](https://github.com/black-forest-labs/flux2/blob/main/src/flux2/util.py) For I25/I26 only, an independently authorized retrieval service may use allowlisted network access; model workers remain offline. Store source URL/date, extracted claim/reference, rights decision and source-to-output binding. Treat retrieved instructions as untrusted data; reject arbitrary URLs/SSRF, private uploads and unsupported factual claims. Search disabled must mean zero search traffic.
9. **Training isolation and provenance.** Keep compilation, teacher inference, student/LoRA training, evaluation and deployment separate. Record dataset rights/consent, train/validation split, base hash, adapter rank/alpha/target modules, optimizer, seed, transforms and metrics. Version consent/UPL independently and bind logs to exposure-time profile/model versions. Start with synthetic adult identities and owned/generated objects, not scraped personal photos.
10. **Qualification, not assumed hardware support.** Pin framework, scheduler, attention kernel, precision and quantizer. Test CUDA and any MPS/CPU backend independently. BFL advertises roughly 13 GB inference for Klein 4B, not a training budget; Qwen Edit/Layered cards identify 20B models (about 40 GB for BF16 parameter storage alone, arithmetic estimate, excluding other components/activations); OmniSVG 8B reports 26 GB in its setup. These are planning signals, not Angelos measurements. [Klein](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B), [Edit](https://huggingface.co/Qwen/Qwen-Image-Edit-2511), [Layered](https://huggingface.co/Qwen/Qwen-Image-Layered), [OmniSVG](https://huggingface.co/OmniSVG/OmniSVG1.1_8B)

## Proposed acceptance suite

**Not run.** Thresholds below are proposed product gates, not upstream benchmark results. Build a rights-cleared fixture set with synthetic adult portraits, fictional characters, asymmetric products, animals, owned style references, text/signage, transparent objects, masks and procedural scenes with known depth/cameras. Use at least 30 cases per relevant category, four fixed seeds for stochastic tasks, held-out subjects, and blinded review. Save all outputs/failures rather than selecting attractive samples. Calibrate perceptual metrics on a pilot set, then freeze thresholds before comparing candidates.

| Test | Proposed acceptance criterion |
|---|---|
| Generation | ≥90% of simple prompts satisfy all annotated object/color/count/layout constraints; separately report difficult prompts and exact OCR transcription. 100% correct requested dimensions/type, finite values and artifact provenance. |
| Img2img and instructions | Evaluate strength levels and edits independently. ≥90% simple instruction success; report unintended scene changes. A no-op preservation mode must return original pixels rather than promise a lossless VAE round-trip. |
| Multi-reference / identity | Test 1/2/3 references, swapped ordering, similar-looking subjects and conflicting instructions. ≥90% correct subject/role binding and ≥90% blinded identity recognition on accepted output sets; report per-subject worst cases. No training-image reuse for held-out evaluation. |
| Style | Cross subjects with unrelated owned style references. ≥85% blinded style recognition while retaining ≥90% content constraints. Measure style-reference subject leakage; do not use style similarity alone as success. |
| In/outpainting | Outside the declared edit-plus-feather support, **maximum absolute pixel difference = 0** after compositing. Test empty/full masks, one-pixel features, edge-touching masks and asymmetric canvas extensions. ≥90% edit success; no visible boundary seam in ≥90% blinded reviews. |
| Canny/depth | Use known synthetic maps and fixed preprocessing. Provisional Canny edge F1 ≥0.80 within 2 pixels at 1024 resolution; depth ordering correct for ≥95% annotated object pairs. Compare against the same seed with conditioning disabled; test conflicting controls and declared strengths. |
| Camera changes | Compare requested 0/±30/±60/90° views against synthetic ground truth. Report viewpoint error, identity and multi-view consistency separately. If exposing numeric camera control, require ≤5° median angular error and stable object geometry; otherwise label the feature approximate text-directed view editing. |
| RGBA layers | Validate requested/returned count, same-canvas alignment, finite alpha in [0,1], documented order and independent manipulation. Proposed reconstruction PSNR ≥35 dB on fixtures; evaluate missing/duplicated objects and halos separately. Changing one layer must not mutate other layer files. |
| Background removal | On known-alpha fixtures, provisional alpha MAE ≤0.03 and boundary F1 ≥0.90; separately score hair, glass, fine structures and shadows. Verify original foreground RGB preservation and composites over black/white/checkerboard backgrounds. |
| Text-to-SVG | 100% parseable, sanitized, renderable output; no embedded raster workaround. ≥90% simple prompt-constraint success. Rasterize at 256 and 2048 pixels; inspect text, topology, editability and path budgets. |
| Raster vectorization | Compare SVG rasterization to held-out source icons/diagrams: provisional SSIM ≥0.95, exact required labels, no missing holes/segments. Score compactness and editable structure separately. Natural photographs form a separate unsupported/stylized category, not an easy-icon average. |
| Precision restoration | Paired synthetic degradations at 2×/4×; compare bicubic/Lanczos, ESRNet and ESRGAN with PSNR/SSIM plus human review. Proposed median improvement ≥0.5 dB over bicubic without new text/identity errors. Disable face enhancement unless separately qualified. |
| Creative upscale | Blinded preference over deterministic scaling ≥65%, with ≥90% global subject/layout retention. Test tile seams and prompt/creativity sweeps; flag generated detail. Do not score invented fine detail as factual restoration. |
| LoRA training | Train only a small approved fixture adapter. Require finite gradients/loss, nonzero adapter updates, unchanged frozen-base hash, held-out identity/style improvement and preserved unrelated-prompt quality. Publish failures and overfitting checks; decreasing training loss alone is insufficient. |
| LoRA load/unload | Save/reload parity on fixed inputs; scale zero reproduces baseline within declared backend tolerance; disabling/unloading restores baseline. Reject wrong base, mismatched shapes and incompatible quantization. Test sequential requests for adapter-state leakage and merge/unmerge drift. |
| Portrait/skin controls (I21–I23) | Use synthetic portraits across skin tones, lighting and degradation. No change outside approved masks; retain identity, skin tone, freckles and facial geometry on ≥95% of reviewed results. Report pore/detail hallucination. Each advertised scalar must have documented units/range and a reproducible effect; unknown `portrait_depth` semantics must fail rather than silently map to denoise strength. |
| Body-part selection (I24) | Test multiple people, left/right limbs, overlaps, glasses/hair and occlusions. Proposed selected-part IoU ≥0.90 on synthetic annotated fixtures; never apply one person's selection to another. Unsupported named-part input must request an explicit spatial mask or fail clearly. |
| Search grounding (I25/I26) | Use a frozen, rights-cleared miniature search corpus with dated product facts, conflicting/outdated results and adversarial page instructions. Require source provenance for 100% of injected factual constraints; ≥90% visible satisfaction of those constraints, zero instruction-following from retrieved pages, and explicit insufficient-evidence behavior. Disabled search must make zero retrieval calls; editing still meets I05 pixel-lock tests. |
| LoRA import (I27) | Round-trip a known safe adapter with content hash unchanged. Reject pickle/executable payloads, oversized files, traversal names, wrong architecture and missing rights/base metadata before GPU admission. Local upload must not push to a public Hub. |
| Parameter routing | Reject image requests containing unsupported `fps_boost`, `interpolate`, temporal `loop` or `generate_audio`. Reject undocumented `retake_mode` values; test any later declared retry policy for unchanged references/masks and explicit seed behavior. |
| Operational / policy | Zero unauthorized network calls, no execution of graph-supplied code, clean missing-model/license failures, cancellation/OOM recovery and bounded batch sizes. Record cold/warm p50/p95 latency, peak VRAM/RAM and all component hashes. GPU success requires real loaded-weight inference, not procedural fixtures. |

## Key remaining gaps and decision gates

- **No demonstrated exact Rhizome equivalence:** no private implementation/catalog is copied into Angelos; equivalence is functional, not an acceptance oracle. Supplied functional requirements are assessed against public evidence and independent proposed tests.
- **Exact geometry and identity:** Qwen viewpoint editing is approximate; restricted object-view models do not establish calibrated scene editing. Identity/style separation and arbitrary multi-reference bindings require empirical qualification.
- **Masks and layers:** native reference editing is not strict masked editing. Pixel lock comes from composition; generative layers are not lossless recovery of an original PSD/SVG or verified physical matting.
- **Creative upscale:** SUPIR is not an unrestricted open-source weight option. The Apache Qwen composition is a candidate, not demonstrated equivalent quality; precision recovery of information absent from the input cannot be promised.
- **Vector licensing/functionality:** OmniSVG 1.1 8B is the stronger permissive-declared candidate than its legacy 3B route; NC training data still needs separate review. StarVector has a verified Apache/OpenRAIL chain discrepancy and released-checkpoint scope limits.
- **Portrait and search parameters:** no exact Enhancor-style skin/depth scalar or automatic anatomical-part selection is established. Search-grounded generation/editing is a proposed retrieval composition, not native web search or deep research. LoRA upload is an unimplemented admission layer, separate from training/loading.
- **Release readiness:** Real-ESRGAN/GFPGAN weight-license specificity, dependency manifests, immutable revisions, hardware budgets and every acceptance score remain unqualified. No production admission or implementation follows merely from this document.
